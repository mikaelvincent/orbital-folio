Separate readers, project details, contact forms, admin/database workflows and unchanged background algorithms were explicitly deferred; they receive no incompleteness deduction and no new passing claim.

## Verified results

- **Portrait composition:** The [production 390-pixel overview](evidence/portrait-ladder-revision/production-phone390-overview.jpg), [320-pixel overview](evidence/portrait-ladder-revision/phone320-overview.jpg) and [768-pixel tablet](evidence/portrait-ladder-revision/tablet768-overview.jpg) show the service/satellite end upward and all four room labels level. The whole craft is visible. The [upright About capture](evidence/portrait-ladder-revision/phone320-about-upright.jpg) confirms the selected-room orientation; the overall craft is intentionally cropped during close approaches.
- **Actual rotation containment:** My [independent reprojection](evidence/portrait-ladder-revision/critic-actual-roll.json) tests all eight conservative hull corners using each recorded camera position, quaternion and roll. Across 97 rotation frames in each of the 320×844 entry, 320×844 return and 320×1024 entry traces, no corner leaves the viewport or depth range. The tall trace records the expanded far plane of approximately 100.37. This closes the earlier fixed-80 far-plane defect. Only the actual rotation phase is assessed as full-craft framing; this is not a claim about every possible viewport or arbitrary retarget.
- **Ladder lighting and route:** The [149-frame traversal](evidence/portrait-ladder-revision/ladder-transit-trace.json) contains 73 frames classified from actual walkway position and reaches level 1.0. The [independent summary](evidence/portrait-ladder-revision/critic-ladder-states.json) confirms idle 0.1, settled in-room hover 0.5, and return to 0.1 when not traversing or hovering. Rotation pullbacks keep the walkway at 0.1. These values are material multipliers, not measured screen luminance; changes ease between levels. Source separately preserves exterior lighting and adds no walkway emitters.
- **Mounted signs:** I inspected the production [rest](evidence/portrait-ladder-revision/production-about-signs.jpg), [motion](evidence/portrait-ladder-revision/production-about-signs-motion.jpg) and [settled drag](evidence/portrait-ladder-revision/production-about-signs-drag-settled.jpg) images. The signs remain mounted and readable. Current source separates previously coincident backing/enamel faces and uses matte ink with filtering and depth bias. The [browser record](evidence/portrait-ladder-revision/browser-qa.json) shows changed camera angles, the same About URL and renderer, and unchanged physical label/portal transforms. These stills and structural checks support the correction; they cannot prove the complete absence of temporal aliasing.
- **Focused model proof:** The [current model audit](evidence/portrait-ladder-revision/model-audit.json) reports 40 lighting cases, 18 sign checks, 12 portrait checks, 162 passage rays and 162 visibility poses, with zero blocked poses. I reviewed these results alongside actual images rather than treating a CPU audit as visual approval.
- **Build and runtime:** [Typecheck](evidence/portrait-ladder-revision/typecheck.txt), [lint](evidence/portrait-ladder-revision/lint.txt) and [build](evidence/portrait-ladder-revision/build.txt) logs pass. They cover desktop overview, About rest/motion/settled and a 390-pixel overview. These are browser callback intervals on one desktop host, not GPU timings, field Core Web Vitals, a physical-phone benchmark or evidence of a speed improvement.

## Remaining limits

The 320×844 entry and return traces each last about **7.9 seconds**; the 320×1024 entry lasts **8.9 seconds**, including the pullback and approach. Rotation itself takes about 1.6 seconds. Preserving the complete craft avoids clipping, but the long journey makes navigation feel less immediate. This is the most useful next polish opportunity.

Ordinary doorway down-arrows are intended to point at the opening below an overhead sign; ladder arrows indicate deck travel. That convention is defensible but can be ambiguous before visitors learn it. Physical side labels remain small and oblique on narrow phones, and fine lettering or contact shading may still show subpixel aliasing. Current overview clouds are stylized rather than photographic.

This pass does not establish native physical-touch behavior, OS screen-reader behavior, a fresh complete accessibility audit, arbitrary rapid retarget/orientation combinations, or performance across low-end hardware. Retained semantic navigation and reduced-motion paths were inspected in source; earlier broad tests were not relabeled as new evidence. No deferred interface was tested to raise this score.

The historical remote-hosting SIWC registration incident remains separate from this local render delivery. This report does not claim a newly deployed public website.

## Reproduction

From the repository root, run `node docs/evidence/portrait-ladder-revision/critic-actual-roll.mjs .` to reproduce the independent trace projection. It uses the installed Three.js package and Node's TypeScript support and writes the adjacent `critic-actual-roll.json`. The [script](evidence/portrait-ladder-revision/critic-actual-roll.mjs) was formatted with oxfmt and passes targeted oxlint. The implementation's bounded model check is `node scripts/portrait-ladder-audit.mjs`. All evidence linked above is packaged in the repository.
