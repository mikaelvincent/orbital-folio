## Findings resolved in this review

The first close-room captures exposed half of a large exterior word at the bottom edge. Final Projects, Experience, About and Contact captures remove that redundant ink while retaining the physical collar and clear upper header. This is a deliberate compromise on narrow screens: the scene keeps all nine compartments visible rather than zooming so far that corner controls disappear. Overview labels return on their fixed hull or portrait collar locations.

The initial About header obstruction and docking-brace intrusion are corrected. The mounting audit reports 513 passed checks against model hash `01042bb8d1cab8c0d1e18319b1cc86adfbde366c82aeaf9ce50892a4824218fa`, including centered docking geometry, wall engagement/clearance, dish support, label-state behavior and reader/header consistency. Those are source/geometry checks. The audit explicitly uses synthetic font metrics and does not render pixels; the final and private-label browser screenshots provide the separate visual evidence.

The label helper measures text and reduces font size proportionally rather than using horizontal compression. Twelve fixed plaque definitions cover hull, portrait collar and interior header roles across four rooms. The browser admin round trip demonstrates actual data-driven changes, including “Notes from the maker” on the physical About header. Navigation may ellipsize long labels while retaining their full text for accessible names and titles.

The renderer now refreshes effective DPR on viewport resize and bounds the drawing buffer to four million pixels. This corrects the observed stale DPR2 buffer after the viewport tool changed native DPR to1. The change is deterministic; no unverified adaptive-feedback controller or speculative shader optimization was introduced.

## Motion and environment evidence

Ocean rotation is 0.003rad/s, twice the previous rate. Cloud rotation is 0.0072rad/s, approximately 3.43 times its previous rate. The cloud field uses quintic interpolation, rotated octave domains and gradient-driven mip sampling. Its finer detail remains procedural; there are no day/cloud image downloads.

The environment audit samples 3,600 active seconds: 515 meteor groups, 644 events, observed group gaps approximately 5.08–8.86 seconds, maximum two visible actors and approximately 3.36% overlapping duty time. Recorded overview diagnostics include an actual two-meteor event; this is stronger evidence than merely allocating two actors. Start/duration limits keep the events clear of their cycle boundary.

Generated environment texture allocation is 474,357 bytes desktop / 81,141 bytes mobile, excluding other scene assets, framebuffers and shared renderer resources. These are allocation figures, not proof of GPU frame time.

The two frozen non-neutral browser samples preserve active time 16.844, position `-5.0761,4.0416,18.4670`, quaternion `-0.103086,-0.134592,-0.014080,0.985424`, hover offset and environment rotations. The actual interrupted trace retargets Contact to About approximately 34ms later while carrying nonzero controller velocity. The current standalone controller tests also verify bounds and convergence. No mathematical test is substituted for the recorded renderer behavior.

## Performance interpretation

The earlier production Projects sample remains part of the result: effective DPR1, buffer 1440×1000, settled camera, median 66.6ms / p95 84.9ms, with 271/360 intervals above 50ms. It cannot be dismissed as the earlier stale-DPR mismatch.

The paused-renderer control records 180 foreground display callbacks over approximately 4.25 seconds, median 17.4ms / p95 50ms. The shadow experiment changes from approximately 52/84ms with shadows to 17.1/35.2ms without them, then 17.2/33.5ms after restoring them. That sequence does **not** establish a shadow-related cause or a successful optimization.

The final settled production repeat, after completed preview surfaces were closed, is much faster without a shader change. This establishes that the final build can render smoothly in the measured local conditions; it does not prove why the earlier run slowed down. No universal 60fps, low-end-phone thermal, independent GPU-timing or field Core Web Vitals result is claimed. The performance score retains the uncertainty.
